# 第 9 章：设计一个网络爬虫

## 引言
**网络爬虫**，也称为蜘蛛或机器人，用于发现和收集网络内容，例如网页、图片和视频。本章聚焦于为**搜索引擎索引**设计一个可扩展的网络爬虫。

### 网络爬虫的应用
1. **搜索引擎索引：**收集网页以创建可搜索的索引（例如 Googlebot）。
2. **网页存档：**保存网页数据以供未来使用（例如美国国会图书馆）。
3. **网页挖掘：**从网页数据中提取知识（例如对股东报告进行财务分析）。
4. **网页监控：**检测版权或商标侵权行为。

### 设计挑战
一个优秀的网络爬虫必须解决以下问题：
- **可扩展性：**使用并行化处理数十亿个页面。
- **健壮性：**处理错误的 HTML、崩溃和恶意链接。
- **礼貌性：**避免用过多请求压垮服务器。
- **扩展性：**以最小的改动支持新的内容类型。

---

## 第 1 步：理解问题

### 需求
1. 每月爬取**10 亿个网页**（每秒 400 个页面，峰值 800 QPS）。
2. 只收集**纯 HTML 内容**。
3. 跟踪新增和更新的页面。
4. 忽略重复内容。
5. 将爬取的数据存储 **5 年**，需要约 30 PB 的存储空间。

## 第 2 步：高层设计

### 组件

1. **种子 URL：**爬虫的起始点。
    - 需要具有选择性，作为良好的起点，使爬虫能够利用它遍历尽可能多的链接。
    - 可以基于地域（基于不同的热门网站），也可以基于主题。
    - 策略：按地域或主题分类（例如体育、医疗）。

2. **URL 前沿：**存储待下载的 URL。
   - 实现为 **FIFO 队列**。

3. **HTML 下载器：**从 URL 前沿提供的 URL 下载网页。

4. **DNS 解析器：**将 URL 转换为 IP 地址。

5. **内容解析器：**校验并解析网页。
   - 丢弃格式错误的页面。

6. **内容已见过？：**使用哈希比较检查重复内容（比较两个网页的哈希值）。

7. **内容存储：**将 HTML 页面存储在磁盘上（热门内容放在内存中以降低延迟）。

8. **URL 提取器：**从解析后的页面中提取新的链接。

9. **URL 过滤器：**排除黑名单或错误的 URL。

10. **URL 已见过？**跟踪已访问的 URL 以避免重复。

11. **URL 存储：**存储已访问过的 URL。


---

### 工作流程
1. 将**种子 URL**添加到 URL 前沿。
2. **HTML 下载器**获取 URL，并通过 DNS 解析器解析其 IP。
3. **内容解析器**校验内容并将其传递给“内容已见过？”组件。
4. 如果内容是新的，则通过 **URL 提取器**提取链接。
5. 过滤并将唯一的链接添加到 URL 前沿。

## 第 3 步：深入探讨关键组件
### DFS/BFS
-  可以将网络视为一个有向图，其中网页是节点，超链接（URL）是边。
-  图遍历通常使用 BFS，因为深度可能非常深，因此 DFS 并不理想。
-  标准 BFS 没有考虑 URL 的优先级，并非每个页面都具有相同的质量和重要性。


### URL 前沿
- **礼貌性：**
    - 确保同一时间对每个主机只有一个请求。在两个下载任务之间添加延迟。
    - 使用从主机名到队列以及工作（下载）线程的映射。
    - 每个下载器线程都有一个独立的 FIFO 队列，并且只从该队列下载 URL。

        <img src="./images/politeness.png" alt="礼貌性" width="500">

    - **队列路由器：**确保每个队列（b1、b2、… bn）只包含来自同一主机的 URL。
    - **映射表：**它将每个主机映射到一个队列。
    - **队列选择器：**每个工作线程映射到一个 FIFO 队列，并且只从该队列下载 URL。队列选择逻辑由队列选择器完成。
    - **工作线程 1 到 N。**工作线程从同一主机顺序下载网页。可以在两个下载任务之间添加延迟。

- **优先级：**
    - 为重要页面分配更高的优先级（例如根据 PageRank 或更新频率）。

        <img src="./images/prioritizer.png" alt="礼貌性" width="500">
    
    - **优先级计算器：**它以 URL 作为输入并计算优先级。
    - **队列 f1 到 fn：**每个队列都有一个分配的优先级。高优先级的队列被选中的概率更高。
    - **队列选择器：**随机选择一个队列，并偏向于优先级更高的队列。
    - **前端队列：**管理优先级
    - **后端队列：**管理礼貌性

- **新鲜度：**根据更新历史或重要性重新爬取。


### HTML 下载器
- **Robots.txt 合规：**遵守 robots.txt 文件中的规则。
- **性能优化：**
  1. 使用多台服务器进行分布式爬取。
  2. 使用 **DNS 缓存**避免重复查询。
  3. 在地理上分散部署爬取服务器以加快下载速度。
  4. 使用较短的超时时间以避免缓慢或无响应的服务器。

### 健壮性
1. **一致性哈希：**在服务器之间有效地分配负载。
2. **错误处理：**防止异常导致系统崩溃。
3. **数据校验：**确保内容完整性。

### 扩展性
- 为新内容类型添加模块（例如 PNG 下载器、网页监控器）。
- 示例：插入一个模块来监控网页内容是否存在版权侵权。

    <img src="./images/extensibility.png" alt="礼貌性" width="600">

### 避免问题内容
1. **重复内容：**使用哈希比较进行检测。
2. **爬虫陷阱：**使用 URL 长度限制等技术避免无限循环。
3. **数据噪声：**过滤广告或垃圾信息等无关内容。

---

## 第 4 步：总结
### 关键要点
1. 网络爬虫必须平衡可扩展性、健壮性、礼貌性和扩展性。
2. **礼貌性**可以防止服务器过载，而**优先级**确保重要页面被优先爬取。
3. 高效的存储和错误处理对于处理大规模爬取至关重要。

### 其他考虑因素
- **服务端渲染：**处理由 JavaScript 或 AJAX 生成的动态内容。
- **反垃圾措施：**排除低质量或无关的页面。
- **数据库分片：**使用复制和分片扩展数据层。
- **水平扩展：**使用无状态服务器高效地扩展爬取任务。
- **分析：**收集并分析数据以获取洞见。
