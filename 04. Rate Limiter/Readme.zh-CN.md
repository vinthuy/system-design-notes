# 第 4 章：设计限流器

## 引言
本章探讨限流器的设计与实现——限流器是一种系统组件，用于控制客户端或服务发出的流量速率。限流器对于防止滥用、降低成本以及确保服务器资源的稳定性至关重要。其使用示例包括限制发帖、创建账号和领取奖励。

## 限流带来的好处
- **防止 DoS 攻击：** 拦截过量调用以避免资源耗尽。
- **降低成本：** 限制不必要的请求以减少服务器开销。
- **防止过载：** 过滤掉过多请求以稳定服务器性能。

## 第 1 步：理解问题
### 关键特性
- 服务端 API 限流器。
- 支持多条限流规则。
- 处理分布式环境中的大规模系统。
- 可选择独立服务或应用层代码。
- 在用户被限流时告知用户。

### 需求
- 精确的请求限流。
- 极小的延迟。
- 低内存占用。
- 分布式能力。
- 清晰的异常处理。
- 高容错。

## 第 3 步：限流算法
### 1. 令牌桶
<div style="margin-left:2rem">
  <img src="./images/token-bucket.png"  alt="令牌桶算法" width="550">
</div>

- **描述：** 令牌以固定速率被添加到桶中；每个请求消耗一个令牌。
- **参数：** 桶大小与填充速率。
- **优点：** 易于实现、内存高效、支持流量突发。
- **缺点：** 需要谨慎调参。



### 2. 漏桶
<div style="margin-left:2rem">
  <img src="./images/leaking-bucket.png"  alt="漏桶算法" width="550">
</div>

- **描述：** 使用 FIFO 队列以固定速率处理请求。
- **优点：** 内存高效、流出速率稳定。
- **缺点：** 流量突发可能延迟最近的请求。
  

  示例：https://github.com/uber-go/ratelimit



### 3. 固定窗口计数器
<div style="margin-left:2rem">
  <img src="./images/fixed-window-counter.png"  alt="固定窗口计数器" width="550">
</div>

- **描述：** 将时间划分为固定区间，并使用计数器限制请求。
- **优点：** 简单，对特定用例高效。
- **缺点：** 窗口边缘的流量尖峰可能超出限制。

- 时间窗口边缘的突发流量
可能导致超过允许配额的请求通过。

## 进阶考量
### 分布式环境
- **挑战：** 竞态条件、同步问题。
- **解决方案：** 使用 Redis 中的锁、Lua 脚本或有序集合。采用集中式数据存储进行同步。

### 性能优化
- 多数据中心部署以降低延迟。
- 采用最终一致性模型进行同步。

### 监控
- 定期分析以确保算法有效性，并按需调整规则。
